二、目标系统与网络环境

目标硬件是 Intel N100，4 核；宽带 1000 Mbit/s，物理 LAN 口 2.5 Gbit/s。目标运行环境是 PVE 的 LXC，PVE 当前内核由用户提供为 7.0.14-8-pve。编译服务器的内核不是这个 PVE 内核。
PVE 上目前运行 iKuai 主路由、OpenWrt 虚拟机、两台 AdGuard Home：

- OpenWrt：192.168.0.2/24，单 LAN 网口，上游网关 192.168.0.1。
- 国内 ADG：192.168.0.3，上游网关 192.168.0.1。
- 国外 ADG：192.168.0.4，上游网关 192.168.0.2。
- 两台 ADG 的系统 DNS 是 223.5.5.5，去广告及加密上游仍由独立 ADG 服务承担。
- PPPoE 只有 IPv4，DHCPv6 客户端关闭。
- 3 个物理口直通给 iKuai（1 WAN、2 LAN）；剩余管理口在 PVE 公共 LAN 网桥上，连接 iKuai/OpenWrt/ADG。

现有 OpenWrt 已修好 Passwall2 双 ADG 分流，迁移必须保留其语义：国内 DNS 发 .3，国外 DNS 发 .4；访问 .3/.4 的本地 DNS 链路保持 LAN 直达；.4 的上游外联通过代理，.4 的 DNS 请求使用独立处理路径，避免“全局 DNS -> .4 -> DNS 劫持 -> 全局 DNS -> .4”递归。全局 FakeDNS 关闭，使用 IPv4；单网口网关禁止 ICMP send/accept redirects；当前 PW2 依赖 sing-box、Xray 和 HAProxy 负载均衡。

六、PVE LXC 与内核兼容，属于必须处理的工程内容

LXC 共用 PVE 内核。容器里 OpenWrt 编出来的 .ko 绝不能作为 PVE 7.0.14-8-pve 的模块加载；在编译服务器加载也没有意义。编译很多 kmod 不等于目标宿主具备功能。
保留真实包依赖元数据，同时检查和适配 CT 启动脚本、模块自动加载配置，避免尝试加载不匹配模块产生持续故障。不要用 --force-depends、假内核包、伪造 uname 或允许 SYS_MODULE 掩盖问题。

输出两部分明确分工：
- CT 内：用户空间程序、fw4/nft 规则、策略路由、IPv4 forwarding、DNS、服务管理。
- PVE 宿主：veth/bridge、网络命名空间、连接跟踪/NAT/REDIRECT、nft_tproxy/nft_socket、策略路由能力、tun/TAP、inet_diag 等实际内核能力。

提供针对正在运行的目标内核的只读预检查、按需加载/持久化方案以及 CT 内实际功能测试。不能单凭 lsmod 判定缺失，需区分 built-in 与 module；不能把本机 6.8 内核测试冒充目标 PVE 7.0 内核测试。不要自行编译替换 PVE 内核；若发行内核确实缺功能，给出证据和单独处理方案。

参考 LXC 项目的 OpenWrt 镜像定义制作有版本记录的容器适配补丁：控制台、sysntpd（时钟由 PVE 管理）、dnsmasq/procd jail 等。vlmcsd 的 procd jail 也要验证，保留合适的服务用户。优先非特权 CT、ostype=unmanaged、默认 AppArmor、精确 /dev/net/tun 映射；根据具体拒绝日志解决权限，不把全特权/unconfined/开放所有设备当作默认方案。nesting/keyctl 不是加速选项。

提供 CT 配置示例和安装说明：单 veth 接用户现有公共 LAN 网桥，IP 由 OpenWrt 管理；PVE 外层防火墙若启用，要允许转发终端的源地址。初始建议 2 核、1024 MiB 内存上限、4 GiB rootfs，按实测调整。模板默认 DHCP/RA 关闭，不预设会与现网 192.168.0.2 冲突的地址。不要在编译服务器执行修改 PVE 网络的命令。

七、高效组件和性能目标

必须主动检查并尽量启用对 N100 和该拓扑有实际收益的组件；不要用“默认即可”略过性能工作，也不要把“所有模块全开”当成优化。
- 先确保 nftset、TCP/UDP 透明代理、socket/TPROXY、策略路由、TUN/TAP 等功能完整。
- 核实用户态核心正常使用 AES-NI 等指令加速；默认使用兼容 N100 的 x86-64 基线。禁止按远程编译服务器 CPU 使用 -march=native。若采用 GOAMD64 v3 或其他特定指令配置，验证 N100 完整指令支持及实际收益，保留兼容构建方案。
- 审查正常的 checksum/GRO/GSO/TSO 能力，不统一关闭网卡卸载；以测得的问题为依据调整。
- 检查 RSS/RPS/队列/IRQ 和 CPU 争用。三个直通物理口归 iKuai；PVE 只管理公共 LAN 物理口和自己的网桥/veth。不要在 CT 中假装设置物理网卡就已生效。
- flow offload 默认保持关闭并说明依据：它主要加速 FORWARD，不能加速代理用户态加解密，且需验证与分流/策略路由的交互。若发现直连流量可从软件 offload 获益，给出限定范围和可回滚的 A/B 测试；不得无证据声称它必然与所有代理冲突。
- BBR 是可选实验，主要针对本机终止的 TCP 代理连接；不能宣称它加速纯转发、所有 UDP、QUIC 或 ZeroTier。
- 不因 N100 或 PVE 内核版本较新就宣称具备硬件 NAT，不堆砌 NSS/SFE 等不适用的加速补丁。
- 保持 IPv4 forwarding，并关闭单网口网关的 ICMP send/accept redirects；不要为性能改变已经正确的双 ADG 路由语义。

分开测试同网段 2.5G 二层互传、经 CT 的直连三层吞吐、代理吞吐、ZeroTier 吞吐和空闲/负载资源占用。普通同网段内网互传通常不经过 OpenWrt 三层转发。没有目标 N100 和完整链路就报告测试方法与待测项，不能靠另一台 x86 编译机的成绩声称已达到 N100 2.5G 或千兆代理。
